# 실사용 기록 — 회의실 예약 시스템

TriAgent Control로 실제 풀스택 프로젝트(`meeting-room-booking`: FastAPI + SQLite, React + Vite)를 기능 단위로 만들면서 생긴 문제와 수정을 적는다. 큰 구현은 TriAgent의 Claude Code(구현 담당)가 맡고, 사람(운영자)은 계획 승인·결과 확인·TriAgent 수정을 맡는다.

## 준비 (2026-11-01)

- 운영자가 만든 것: 폴더, git, `.venv`(fastapi·uvicorn·pytest·httpx), Vite React 템플릿 + Vitest, `/api/health` 하나와 테스트 하나, 최상위 `package.json`의 `test`(화면 Vitest + 서버 pytest)·`build` 스크립트.
- 최상위 스크립트를 둔 이유: TriAgent 자동 검증은 작업 폴더 최상위의 `package.json`과 `tests/`만 찾는다. `backend/`·`frontend/`로 나눈 프로젝트는 최상위 스크립트가 없으면 "자동 검증 없음"이 된다.

## 문제 기록

### 1. 세션 worktree에서 화면 테스트·빌드가 항상 실패 (수정함)

- **증상**: 모델을 부르기 전 점검에서, 세션 worktree의 `npm test`·`npm run build`가 `'vitest'은(는) 내부 또는 외부 명령... 아닙니다`로 실패.
- **원인**: worktree에는 Git이 추적하지 않는 의존성 폴더가 없어서 사용자 폴더의 것을 연결하는데, 최상위(`.venv`, `node_modules`)만 연결했다. 이 프로젝트의 `node_modules`는 `frontend/` 아래에 있다.
- **영향**: 모노레포 구성에서는 자동 검증이 매번 실패해, 파이프라인이 통과할 수 없었다.
- **수정**: `triagent/domain/gitops.py` — 한 단계 아래의 의존성 폴더(`frontend/node_modules`, `backend/.venv` 등)도 연결하고, 정리할 때도 그 연결만 끊는다. 회귀 테스트 추가.
- **확인**: 같은 점검을 다시 돌려 worktree에서 `npm test`(화면 1 + 서버 1)·`npm run build` 통과, 원본 `frontend/node_modules`와 사용자 브랜치·파일은 그대로.

### 2. 기능을 이어서 만들 때 이전 기능이 다음 세션에 없음 (운영 방식으로 해결)

- **증상(예상)**: 세션마다 사용자 폴더의 마지막 커밋에서 worktree를 만든다. 기능 1의 결과는 `triagent/<세션ID>` 브랜치에만 있으므로, 기능 2 세션은 기능 1 없이 시작한다.
- **운영 방식**: 기능 하나가 끝나면 운영자가 결과를 확인하고 세션 브랜치를 `main`에 병합(fast-forward)한 뒤 다음 기능을 시작한다.
- **개선 후보**: 대시보드에 "결과를 내 브랜치에 반영" 단추 (테스트 통과·충돌 없음일 때만).

### 기능 3 — 주간 달력 화면 (1차 실행 중단 → 수정 후 재실행)

#### 3. 구현 턴 하나 만에 "최대 토큰 200,000 도달"로 세션 종료 (수정함)

- **증상**: 화면 구현 턴(132초, 비용 $0.53) 직후 세션이 끝났다. 테스트·검토를 한 번도 거치지 않았고 커밋도 0개.
- **원인**: 그 턴의 실측 사용량 24만 3천 개 중 20만 2천 개(83%)가 캐시 읽기였다. 캐시 읽기는 도구를 부를 때마다 같은 문맥을 다시 읽은 양이라, 작업량이 아니라 도구 호출 수에 비례한다. 코딩 한도가 이것까지 세서, 파일을 여러 개 만드는 큰 작업은 한 턴 만에 한도를 넘었다.
- **수정**: 한도 판정에만 "처리 토큰"(캐시 읽기 제외: Claude의 `cache_read_input_tokens`, Codex의 `cached_input_tokens`)을 쓴다. 화면의 실측 토큰 표시는 그대로. 회귀 테스트: 같은 사용량(실측 283,544 / 처리 41,779)이면 한도에 걸리지 않음.

#### 4. 빌드 결과물이 에이전트 변경으로 잡힘 (수정함)

- **증상**: Claude가 검증하려고 `npm run build`를 돌려 생긴 `frontend/dist/`(6개 경로)가 변경 파일로 잡혔다.
- **영향**: 변경 파일 한도(50개)를 채우고, 사이클 커밋 때 `git add`가 "ignored" 오류(exit 1)로 실패한다 (임시 저장소에서 재현).
- **수정**: 변경 감지 직후 `git check-ignore`로 `.gitignore`에 걸리는 경로를 뺀다 (이미 추적 중인 파일은 그대로 변경으로 본다). 역할 범위 검사·diff·커밋 모두 이 목록을 쓴다.

- **1차 실행 처리**: 세션은 끝났고 worktree의 구현은 커밋되지 않았다. 검증·검토를 거치지 않은 결과라 버리고, 수정한 TriAgent로 기능 3을 처음부터 다시 실행한다.

### 기능 5 — 로그인과 권한 (1차 실행 중단 → 수정 후 재실행)

#### 5. 테스트 턴 직후 "최대 diff 2,000줄 도달"로 끝나 구현이 통째로 버려짐 (수정함)

- **증상**: Claude 구현(248초) → Antigravity 테스트(320초, "86개 통과")까지 했는데, 그 직후 diff 한도(2,390줄 > 2,000)에 걸려 세션이 끝났다. 자동 검증·검토·커밋을 하나도 거치지 않아 커밋 0개.
- **원인**: 크기·시간·토큰 한도를 매 단계마다 확인해서, 사이클 중간에 걸리면 그때까지 한 구현이 검증·커밋 없이 남는다. 또 2,000줄은 테스트까지 포함한 풀스택 기능 하나에도 모자랐다.
- **수정**:
  - 크기·시간·토큰 한도는 **사이클 경계(새 사이클 시작 직전)에서만** 확인한다. 진행 중인 사이클은 검증·검토·커밋까지 마치고 멈춘다. 실패 반복 한도는 언제나 확인한다.
  - diff 기본 한도 2,000 → 5,000줄.

#### 6. Claude가 서버 테스트를 못 돌림, 어떤 명령이 막혔는지도 알 수 없음 (수정함)

- **증상**: Claude가 "`.venv` 실행이 허용되지 않아 backend pytest를 돌리지 못했다"고 보고. 작업 로그에는 "Bash 실행"만 남아 어떤 명령이 막혔는지 확인할 수 없었다.
- **수정**:
  - 작업 로그에 Bash 명령 원문과, 도구가 거부·실패했을 때 그 사유("도구 실행 실패: …")를 남긴다.
  - 테스트 명령 권한에 절대 경로·`./`로 부른 가상환경 python(`*python.exe -m pytest*` 등)과 `npx vitest`를 추가. 실행 파일 이름이 python으로 끝나야 하고, `&&`로 이어 붙인 명령은 Claude Code가 따로 검사한다.
- **확인**: 실제 Claude 호출로 절대 경로 python의 unittest는 실행, `-c` 임의 코드와 이어 붙인 명령은 거부.

- **1차 실행 처리**: 검증·검토를 거치지 않은 결과라 버리고, 수정한 TriAgent로 기능 5를 처음부터 다시 실행한다.

#### 7. 테스트 담당 턴이 600초 제한을 넘겨 실패 (수정함)

- **증상**: 재실행에서 Claude 구현(247초, 이번에는 가상환경 python으로 서버 테스트 55개를 직접 돌려 통과 — 수정 6 효과, 실행 명령도 기록에 남음)은 됐지만, Antigravity 테스트 턴이 600초 제한을 넘겨 "응답 없음"으로 실패하고 세션이 멈췄다.

- **수정**: Antigravity 턴당 제한 600 → 1,200초 (`AGY_TIMEOUT_SECONDS`).

#### 재실행 결과와 운영자 확인

- 계획이 1차보다 꼼꼼했다: 동시 가입 시 둘 다 admin이 되는 경쟁을 `BEGIN IMMEDIATE`로 막고, 예약자가 없는 기존 예약은 admin만 고치게 했다.
- **보안 점검 (운영자, 병합 전)**: pbkdf2 24만 회 + 사용자별 salt, `compare_digest`, 없는 아이디도 같은 시간이 걸리게 가짜 해시 계산, 세션 토큰 `secrets`, HttpOnly·SameSite=Lax 쿠키, 8시간 만료, 로그아웃 시 서버 세션 삭제. `/api/health`·`/api/auth/*` 외 모든 API에 로그인 필요, 회의실 생성 admin 전용, 변경·삭제(반복 일괄 포함) 본인·admin 전용 — 막을 문제 없음.
  - 실제 배포 전 보완 거리 (이번 요청 범위 밖): HTTPS면 쿠키 `Secure`, 로그인 시도 횟수 제한, 세션 토큰을 해시로 저장, "첫 가입자가 관리자"이므로 공개 전에 관리자 계정을 먼저 만들 것.
- **실제 화면 확인**: 로그인 화면 → 회원가입 안내("아이디는 3~30자, 비밀번호는 8자 이상") → 첫 가입자 "manager1 (관리자)", 두 번째 "member01 (사용자)". 사용자에게는 회의실 추가 폼이 없고 남의 예약 상세에 삭제 단추가 없다. API로도 남의 예약 삭제·변경, 회의실 생성이 403. 관리자는 member01 예약 상세에 "예약자: member01"과 삭제 단추. 틀린 비밀번호와 없는 아이디가 같은 401·같은 문구.
- `main` 병합 후 `npm test` 통과 (화면 23, 서버 66).
- 발견한 기능 빈틈: 회의실 추가 폼이 "회의실이 하나도 없을 때"만 나와서 관리자가 두 번째 회의실을 화면에서 추가할 방법이 없다 (기능 3 요청을 그렇게 썼다 — 구현 결함이 아니라 요구사항 빈틈). 기능 6 요청에 함께 넣는다.

## 운영 메모

- 대시보드의 승인 단추를 클릭 도구로 누르면 브라우저 패널이 화면에 안 그려져 실패할 때가 있다. 페이지 안에서 단추를 직접 눌러 해결.
- 중간 안내를 영어로 쓰는 실수가 반복돼 사용자 지적을 받았다 (운영자 쪽 문제, TriAgent와 무관).
