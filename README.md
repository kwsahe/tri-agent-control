# TriAgent Control

Codex, Antigravity, Claude Code를 하나의 웹 대시보드에서 실행하고 관제하는 로컬 멀티 에이전트 오케스트레이터입니다. 세 모델이 같은 대화 문맥을 공유하며 토론, 역할 분담, 실제 코딩, 검증과 최종 보고를 수행합니다. 사용자는 실행 중에도 대상 모델을 선택해 질문하거나 방향을 바꾸고, 승인·보류·중단을 직접 결정할 수 있습니다.

## 주요 기능

### 세 모델 통합 관제

- Codex, Antigravity, Claude Code 연결 상태와 CLI 버전을 확인합니다.
- 세 모델 중 필요한 모델만 활성화해 세션을 시작할 수 있습니다.
- 모델별 세부 모델과 추론 강도 또는 프리셋을 선택할 수 있습니다.
- 비활성 모델 정보도 나머지 모델의 프롬프트에 전달됩니다.
- 각 모델의 공식 아이콘, 현재 상태, 선택 모델을 대시보드에 표시합니다.

### 실행 모드

세 가지 모드가 있고, 시작 화면의 **실행 계획** 상자에 모드·모델 수·예상 호출
횟수·권한·작업 폴더·자동 검증 여부가 실행 전에 표시됩니다.

- **빠른 질문**: 선택한 모델 **1명을 1회만** 호출합니다. 강점 분석·역할 협의·보고
  단계를 생략하고, 사용자가 지정한 길이와 출력 형식을 고정 워크플로보다 우선합니다.
  기본 읽기 전용이며 파일 쓰기를 허용하지 않습니다. (한 문장 질문에 최소 3회
  모델을 호출하던 문제를 피하기 위한 모드입니다.)
- **토론 모드**: 프로젝트 분석, 강점 공유, 반론, 역할 분담과 최종 정리를 수행합니다.
- 일반 토론은 `프로젝트 읽기`와 `읽지 않고 토론` 중 하나를 선택할 수 있습니다.
- `프로젝트 읽기`에서는 세 모델 모두 관련 파일을 읽고, `읽지 않고 토론`에서는 격리된 작업 경로에서 대화 문맥만 사용합니다.
- **코딩 모드**: `PROJECT_PATH.txt`가 가리키는 실제 프로젝트를 읽고 수정합니다.
- 코딩 모드의 승인 전 계획 단계에서는 세 모델 모두 읽기 전용으로 동작하고, 승인 후에는 목표 기반 구현·자동 검증·교차 검토 사이클을 반복합니다.
- 목표 기반 코딩은 사이클, 실행 시간, 토큰, 변경 파일, diff와 반복 실패 한도 중 하나에 도달하면 자동 종료합니다.
- 실행 중에도 토론 모드와 코딩 모드를 전환할 수 있습니다.
- 코딩 지시는 계획 보고로 끝내지 않고 파일 수정과 가능한 검증까지 수행하도록 별도 실행 의도로 전달됩니다.
- 코딩 턴 전후의 파일 변경을 감지하고 unified diff 체크포인트를 저장합니다.
- 체크포인트에서 선택한 파일만 해당 턴 이전 상태로 되돌릴 수 있습니다.
- 대시보드의 `Work Area` 카드에서 Windows 파일 탐색기로 작업 폴더를 직접 선택할 수 있습니다.
- 일반 모드에서는 작업 폴더 권한을 `읽기 전용` 또는 `읽기·쓰기`로 지정할 수 있습니다. 코딩 모드로 전환하면 읽기·쓰기로 자동 고정됩니다.

### 역할 선택과 강제

- 토론 내용을 본 뒤 사용자가 Codex, Antigravity, Claude Code의 역할을 각각 선택합니다.
- 시스템 설계, 백엔드, 프론트엔드, UX·접근성, QA·테스트, 리뷰, 보안, AI·데이터, DevOps, 성능, 제품 기획, 문서, 통합 조정 역할을 제공합니다.
- 같은 역할은 두 모델에 중복 배정할 수 없고, 모델 실행 중에는 역할을 변경할 수 없습니다.
- 역할 지정은 선택 사항입니다. 미지정 모델은 일반 작업자로 정상 실행하며 역할 범위 강제를 적용하지 않습니다.
- 역할이 지정된 모델의 담당 범위 밖 파일 변경이 감지되면 해당 턴을 실패 처리하고 세션을 일시정지합니다. 읽기 전용 역할은 코딩 지시도 검토로 전환됩니다.
- 전역 규칙은 `ROLE_POLICY.md`, 세션의 현재 배정과 변경 이력은 `Roles.md` 하나에 저장합니다. 역할별 MD는 따로 만들지 않습니다.
- 오른쪽 `Roles` 카드와 화면 폭에 관계없이 사용할 수 있는 헤더 역할 설정 버튼을 제공합니다.

### 사용자 개입과 승인

- 질문, 방향 수정, 코딩 실행, 멈추고 답변, 참고 메모 중 개입 유형을 선택할 수 있습니다.
- Codex, Antigravity, Claude Code 중 답변할 모델만 지정할 수 있습니다.
- 메시지를 `[Antigravity] 진행 시작`처럼 시작하면 지정한 모델을 선택된 대상 중 첫 번째로 호출합니다. `[Codex]`, `[Claude]`, `[Claude Code]`도 지원합니다.
- 개입 요청은 정규 진행 단계보다 먼저 처리됩니다.
- 모델이 응답 마지막에 `APPROVE`를 출력하면 토큰은 채팅에서 숨겨지고 승인 창이 열립니다.
- 승인, 거절, 보류를 선택할 수 있으며 보류 상태에서 추가 질문이나 수정 지시를 보낼 수 있습니다.
- 구조화된 `STOP_AND_ASK_USER` 신호가 반환되면 세션을 `WAITING_FOR_USER_RESPONSE`로 저장하고 다음 Agent와 코딩 작업을 차단합니다.
- 질문 선택지는 서버에서 검증하며, 유효한 답변이 기록된 뒤에만 저장된 다음 단계부터 실행을 재개합니다.
- 질문 대기는 서버 재시작 후에도 유지되고 일반 채팅이나 승인 버튼으로 임의 해제되지 않습니다.
- 중단 시 실행 중인 CLI 하위 프로세스도 함께 종료합니다.
- 실패한 턴과 보류된 개입 요청은 재시도할 수 있습니다.

### 에이전트 간 호출

모델이 자신의 담당 범위를 벗어난 검토나 후속 작업이 필요하다고 판단하면 다른 모델을 직접 호출할 수 있습니다.

```text
CALL_AGENT: codex|antigravity|claude | discussion|coding | 구체적인 요청
```

- 호출은 공유 개입 큐에 등록되고 대상 모델이 이어서 처리합니다.
- 자기 자신, 비활성 모델, 중복 호출은 무시합니다.
- 토론 턴에서 코딩 권한을 임의로 위임할 수 없습니다.
- 무한 왕복을 막기 위해 호출 깊이는 2단계, 세션당 호출은 12회로 제한합니다.
- 호출자, 대상, 모드와 요청 내용은 `Agent Calls` 패널에 기록됩니다.

### 실시간 작업 로그

- 모델 실행 중 `Thinking` 카드와 경과 시간을 표시합니다.
- CLI의 추론, 도구 호출, 명령 실행, 파일 읽기·수정, 사용량 이벤트를 실시간으로 보여줍니다.
- 완료된 답변에서 해당 턴의 작업 로그와 변경 파일을 펼쳐볼 수 있습니다.
- 최근 어떤 모델의 대화가 프롬프트에 전달됐는지 표시합니다.
- Python/Node 프로젝트의 테스트·린트·빌드 명령을 감지해 자동 실행하고 `Validation` 패널에 결과를 남깁니다.

### 토큰 사용량 관제

- 전체 세션의 실제 토큰, 경과 시간과 비용을 표시합니다.
- 모델별 세션 누적 점유율의 합계를 100%로 계산해 진행 막대로 보여줍니다.
- **세션 누적 사용량과 현재 컨텍스트 점유율은 완전히 분리해 표시합니다.** CLI가 주는
  턴 단위 usage는 그 턴 안의 모든 내부 호출 합계라, 그대로 컨텍스트 한도로 나누면
  100%를 크게 넘는 값이 나옵니다(실제로 `461.1%`가 표시된 적이 있습니다).
  이제 누적 토큰을 컨텍스트 한도로 나누지 않습니다.
- 현재 컨텍스트는 근거에 따라 `실측`(CLI가 호출 단위 usage를 제공), `추정`(프롬프트
  길이 기반), `알 수 없음` 중 하나로 라벨과 함께 표시합니다.
- 100%를 넘으면 막대만 100%에서 멈추고 **숫자는 실제 값을 그대로 보여주며** 한도 초과를
  따로 표시합니다. 문제를 숨기지 않습니다.
- 비용은 CLI가 보고한 실제 값과 토큰 기반 추정값을 하나로 합치지 않고 따로 보여주며,
  단위(USD)와 계산 근거를 함께 표시합니다.
- `모델별 토큰 추정량` 버튼을 누르면 모델별 상세 카드를 열 수 있습니다.
- 상세 카드에는 점유율, 턴 수, 추정 토큰, 입력, 캐시, 출력과 비용이 표시됩니다.
- CLI가 실제 사용량을 제공하면 실제 값을 사용하고, 제공하지 않는 모델은 `~`가 붙은 문자 기반 추정값을 사용합니다.
- 상세 창을 열어둔 상태에서도 폴링 데이터에 맞춰 값이 갱신됩니다.
- 자동 토큰·비용 제한은 기본적으로 비활성화되어 있습니다.

### 세션과 메모리

- 세션 이름 수정, 검색, 태그, 즐겨찾기, 보관, 삭제와 분기를 지원합니다.
- 분기한 세션은 기존 대화와 설정을 유지한 채 별도 세션으로 이어집니다.
- 모든 대화는 세션별 Markdown 원문과 압축 메모리에 저장됩니다.
- 세션마다 `Profile.md`, `Roles.md`와 모델별 역할 프로필을 생성합니다.
- 대시보드에서 `Profile.md`를 열고 수정해 저장할 수 있습니다.
- 전체 대화를 매번 프롬프트에 넣지 않고 최근 대화와 압축 요약만 전달해 입력 크기를 제한합니다.
- 최종 프롬프트, 공유 문맥과 예상 토큰을 실행 전에 미리 볼 수 있습니다.

## 요구 사항

- Python 3.10 이상
- 별도 Python 패키지 없이 표준 라이브러리만으로 실행 가능
- 사용할 모델의 CLI 설치와 로그인

| 모델 | 기본 명령 | 확인 명령 |
|---|---|---|
| [Codex](https://github.com/openai/codex) | `codex` | `codex --version` |
| [Antigravity](https://antigravity.google/) | `agy` | `agy --version` |
| [Claude Code](https://claude.com/claude-code) | `claude` | `claude --version` |

모든 CLI를 설치할 필요는 없습니다. 세션 시작 시 연결된 모델만 선택할 수 있습니다.

## 시작하기

1. 서버를 실행합니다.

```powershell
python roundtable.py
```

2. 자동으로 열린 [http://127.0.0.1:8765/](http://127.0.0.1:8765/)의 `Work Area`에서 작업 폴더와 읽기·쓰기 권한을 선택합니다. `PROJECT_PATH.txt`를 직접 수정하는 방식도 지원합니다.
3. 주제, 모드, 참여 모델과 세부 모델을 선택합니다.
4. **시작**을 누르고 대화와 작업 로그를 확인합니다.

기본 포트가 사용 중이면 다음 포트를 순서대로 시도합니다. 실제 URL은 터미널에 출력됩니다.

## 기본 실행 흐름

### 토론 모드

1. 활성 모델이 순서대로 프로젝트와 자신의 강점을 분석합니다.
2. 서로의 분석을 확인하고 반론 또는 보완 의견을 냅니다.
3. 담당 영역과 파일 범위를 토론합니다.
4. 사용자가 대시보드의 역할 선택지에서 각 모델의 역할을 확정합니다.
5. 확정 역할과 변경 이력을 세션 `Roles.md`에 저장합니다.
6. 보고 담당 모델이 논의 결과와 다음 행동을 정리합니다.

### 코딩 모드

토론과 역할 합의 후 각 모델이 담당 범위의 실제 파일을 수정합니다. 파일 변경, 작업 로그와 체크포인트를 기록하고 자동 검증을 실행한 뒤 최종 결과를 보고합니다.

> 코딩 모드는 실제 프로젝트 파일을 변경합니다. 실행 전에 대상 프로젝트를 커밋하거나 별도 브랜치에서 시작하는 것을 권장합니다.

### 목표 기반 코딩

코딩 모드는 계획과 사용자 승인이 끝나면 다음 목표 사이클을 제한 범위 안에서 반복합니다.

1. Codex, Antigravity, Claude Code가 차례로 실제 코드를 구현합니다.
2. 구현 묶음이 끝나면 프로젝트 테스트·린트·빌드를 자동 검증합니다.
3. 세 모델이 현재 프로젝트, 변경 내용과 검증 결과를 읽기 전용으로 교차 검토합니다.
4. 보고 모델이 의견 충돌과 다음 구현 우선순위를 하나로 통합합니다.
5. 통합 결과가 다음 사이클의 구현 문맥으로 전달됩니다.

기본 한도는 3사이클, 45분, 추정 20만 토큰, 변경 파일 50개, diff 2,000줄입니다. 연속 실패 또는 동일 오류가 2회 반복돼도 자동으로 멈춥니다. 대시보드의 `중단`을 누르면 현재 CLI 프로세스와 코딩 사이클을 즉시 종료합니다. 이전 `continuous` 세션은 로드할 때 코딩 모드의 현재 목표 사이클 위치로 자동 변환됩니다.

## 프롬프트와 메모리 절약

각 CLI 호출은 독립 실행이므로 모델이 이전 턴을 영구 학습한 상태로 유지되지는 않습니다. TriAgent Control은 다음 정보만 압축해 전달합니다.

- `TEAM_PROMPT.md` 최대 1,400자
- `brief.md` 최근 6줄
- 활성 모델별 최신 발언과 최근 사용자 개입
- 최근 대화 최대 2개, 1,600자
- 메모리 문맥 최대 1,800자
- 전체 프롬프트 기본 최대 5,000자

## 테스트

```powershell
python -m py_compile roundtable.py
python -m compileall roundtable.py triagent tests
node --check static/dashboard.js
python -m unittest discover -s tests -v
```

전체 스위트는 수 초 안에 끝납니다. 테스트는 **자기 자신을 자식 프로세스로 다시
실행하지 않습니다** — 자동 검증 명령 탐지는 `triagent/domain/validation.py`의 순수
함수로 분리돼 있고, 환경(`ToolEnvironment`)을 주입받으므로 pytest 설치 여부와
무관하게 결과가 결정적입니다. 또 TriAgent 자신의 폴더는 검증 대상에서 제외되어
`unittest discover`가 재귀 실행되지 않습니다.

`sessions/`, `roundtable_memory/`, `PROJECT_PATH.txt`, Profile 파일을 읽거나 쓰지

### 실제 CLI 스모크 테스트

실제 모델을 호출하므로 요금과 시간이 듭니다. 자동 테스트가 아니라 수동 검증용입니다.

```powershell
$env:PYTHONPATH='.'
python tests\live_smoke.py            # 세 CLI 모두
python tests\live_smoke.py codex      # 하나만
```

스모크 테스트는 **`TemporaryDirectory` 안에서만** 실행되며 원본 프로젝트 폴더를
작업공간으로 쓰지 않습니다. 실행 전후로 프로젝트 트리 전체의 SHA-256을 비교해
파일이 하나라도 바뀌면 실패로 보고하고, 읽기와 쓰기를 따로 판정하며, 출력에
인증 정보가 섞이면 경고합니다. CLI가 없거나 로그인되지 않았으면 성공으로 위장하지
않고 실패로 남깁니다.

## 보안 범위

서버는 `127.0.0.1`에만 바인딩됩니다. 그것만으로는 브라우저에 열린 **다른 웹페이지가**
`fetch("http://127.0.0.1:8765/stop")` 같은 요청을 보내는 것을 막지 못하므로, 다음
방어를 함께 적용합니다.

- **CSRF 토큰**: 서버 시작마다 예측 불가능한 토큰을 만들고, 상태를 바꾸는 모든 요청
  (`/stop`, `/topic`, `/session/delete`, `/workspace/access`, 프로필 저장 등)에
  `X-CSRF-Token` 헤더 또는 `csrf_token` 폼 필드로 요구합니다. 없거나 틀리면 403입니다.
- **Origin / Host 검증**: Origin 헤더가 있으면 현재 포트의 `127.0.0.1`/`localhost`만
  허용하고, Host 헤더도 로컬 호스트 + 실제 바인딩 포트인지 확인합니다(DNS rebinding 차단).
  포트가 8765~8774 중 어디로 열리든 그 포트를 기준으로 동작합니다.
- CORS 헤더는 내보내지 않습니다. 외부 페이지가 응답을 읽지 못하는 것도 방어의 일부입니다.
- **세션 ID 경로 검증**: 세션 ID는 단일 검증 함수를 거칩니다. 경로 구분자, `..`,
  드라이브 문자, 절대 경로, URL 인코딩 우회를 거부하고, 문자열 검사에 더해 resolve된
  최종 경로가 허용된 부모 폴더 안인지 다시 확인합니다. 읽기·쓰기·삭제·복제·프로필·
  역할·체크포인트 등 모든 경로 진입점에 같은 보호가 걸려 있습니다. 잘못된 ID는 서버를
  죽이지 않고 HTTP 400으로 돌려줍니다.
- 디스크에 형식이 맞지 않는 세션 파일이 있어도 **자동으로 지우거나 옮기지 않고**
  목록에서만 제외하고 경고합니다. 손상된 세션 하나 때문에 전체 목록이 실패하지 않습니다.
- **요청 크기 제한**: Content-Length에 상한이 있으며, 음수·비정상 값은 400,
  과도한 크기는 413으로 거부합니다.
- **체크포인트 소유권**: 체크포인트에는 세션 ID와 작업공간이 함께 저장되고, 롤백할 때
  현재 세션·현재 작업공간에서 만들어진 것인지 확인합니다. 다른 세션이나 다른 프로젝트의
  체크포인트, 그리고 소유권 정보가 없는 레거시 체크포인트는 자동 적용하지 않습니다.
- **작업공간 fail closed**: `PROJECT_PATH.txt`가 없는 폴더를 가리키면 예전처럼 조용히
  TriAgent 자신의 폴더로 대체하지 않습니다. 유효한 폴더를 다시 선택할 때까지 읽기와
  쓰기 모델 실행을 모두 차단하고, 원래 저장된 경로와 함께 차단 상태를 화면에 표시합니다.
  세션에 저장된 작업공간과 현재 선택 경로가 다르면 사용자 확인 없이 실행하지 않습니다.
- 로컬 대시보드는 외부 폰트를 포함해 **인터넷으로 나가는 요청을 하지 않습니다.**
- CLI 출력·점검 로그에서 API 키·토큰으로 보이는 값은 마스킹합니다.

코딩 모드는 로컬 CLI 권한으로 대상 프로젝트를 수정하므로, 각 CLI의 권한 설정과
작업 폴더 경로를 실행 전에 확인하세요.
